# Scalebreaker（中文名待定）

> 原名《港区警报》（Harbor Alert），2026-11-26 更名；内部路径与 Rust crate 名仍按旧约定保留 `harbor`/`gba`。

《Scalebreaker》是 Godot + Rust 的单机 3D 原型，支持 Linux 开发运行和 Android ARM64 调试 APK。四种模式的港区默认是 1,418 × 1,418 米，可分别设置地图边长。默认港区包含 1,718 栋多风格可破坏建筑，道路上不再放置路障，涵盖核心老港区、中央公园与市民广场、摩天商务区、集装箱货运码头、石化炼油储罐区、干船坞造船厂、历史红砖仓库群、环岛海堤与海港灯塔。

整张 1,418 米的港区其实立在一张书桌上：一个 1:1 卧室以桌面沙盘（约 21.27 cm 见方）的形式作为 3D 背景环绕港区，卧室相机按 1:6667 跟随主相机位姿——你在港区里看到的"天空"，是一个女孩房间的墙和天花板。首版设计与验收目标见 [PLAN.md](PLAN.md)（历史文档，保留旧名）。

## 构建与启动

在 Linux x86_64 上使用 Godot 4.7.2、Rust 1.94 和 Cargo。Rust 扩展使用锁定的 `godot` 0.5.5。以下命令从工程根目录运行。

```sh
cargo build --locked --manifest-path rust/Cargo.toml --target-dir rust/target
godot --headless --path . --editor --import
godot --path .
```

也可以在完成构建后，用 Godot 打开 `project.godot` 并按 **F5**。扩展配置位于 `native/harbor.gdextension`。修改 Rust 后重新构建并重启正在运行的游戏。

主菜单的「港区模式」打开二级菜单，可选人类撤离、巨人沙盒、成长模式和大乱斗。成长模式内可选成长模式、旁观者模式或人类模式。「微缩卧室 → 进入卧室」直接操控身高 **1 厘米**的港区人类角色。

电脑端用 **WASD** 移动，鼠标或方向键环视。靠近并面向墙壁或家具后，按住 **空格** 向上攀爬，有空间时可翻上边缘，松开后落下。安卓端使用左侧摇杆移动、右侧滑动环视，长按「按住攀爬」按钮。用 **Esc**、安卓系统返回或触屏上的返回按钮逐级回退。

## Linux x86_64 发布包

通过 Godot 的「编辑器 → 管理导出模板」安装与编辑器版本匹配的 Linux x86_64 模板。先完成上面的开发版构建和资源导入，再从工程根目录运行。

```sh
cargo build --locked --release --manifest-path rust/Cargo.toml --target-dir rust/target
mkdir -p build/linux
godot --headless --path . --export-release "Linux x86_64" "$PWD/build/linux/harbor-alert.x86_64"
./build/linux/harbor-alert.x86_64
```

分发时一起保留 `build/linux/` 里的可执行文件、`harbor-alert.pck` 和 `libharbor.so`。

## Android 调试 APK

使用官方 Godot 4.7.2 和同版本的 Android 调试模板、Rust 1.94、JDK 17、SDK 36、Build Tools 36.1.0 和 NDK 29.0.14206865。在 Godot 编辑器设置的 Android 导出页配置 Java SDK、Android SDK 和调试签名。已有同级 `gtb` 工具链的机器可直接构建。

```bash
rustup target add --toolchain 1.94.0 aarch64-linux-android
harbor_toolchain="$HOME/.local/share/gtb-toolchain"
XDG_CONFIG_HOME="$harbor_toolchain/config" \
XDG_DATA_HOME="$harbor_toolchain/data" \
ANDROID_SDK_ROOT="$harbor_toolchain/android" \
JAVA_HOME="$harbor_toolchain/jdk17" \
GODOT_BIN="$harbor_toolchain/Godot_v4.7.2-stable_linux.x86_64" \
CARGO_BIN="$HOME/.cargo/bin/cargo" \
scripts/build_android.sh
```

产物是 `build/harbor-alert-debug.apk`，包名 `org.gba.harboralert`，仅包含 ARM64，最低 API 24，目标 API 36，支持两个横屏方向。导出保留道路、人物、纹理和废墟碰撞，排除当前场景没有引用的原始楼体资产。Android 使用 Compatibility 渲染，关闭 3D MSAA，默认视距 200 米、阴影距离 95 米。视距可在各模式的设置里调整。移动端界面使用随包分发的 Noto Sans CJK SC 字形子集，许可见 [OFL-NotoSansCJK.txt](assets/fonts/OFL-NotoSansCJK.txt)。

### 安装与真机验收

手机开启 USB 调试并连接电脑后，在工程目录安装。也可把 APK 传到手机上打开安装。

```sh
adb install -r build/harbor-alert-debug.apk
adb shell am start -S -W -n org.gba.harboralert/com.godot.game.GodotAppLauncher
```

1. **启动和三种玩法。** 从应用图标冷启动，确认主菜单与三个模式都能进入，中文和纹理正常。人类撤离用左手拖动摇杆、右手环视，再同时按住疾跑，确认体力下降，松开后恢复。巨人沙盒边移动和环视边点踩踏，确认预警、楼体倒塌和可走废墟都正常。
2. **成长模式。** 确认 1 厘米开局是人类建模、不能踩踏，能捡金币和切换视角。捡金币长到 3 米后确认切换为巨人并解锁踩踏。倒下后观察复活倒计时，确认皮肤不变并再试一次移动。实际成长或在设置中提高初始身高后，检查大型巨人的第一和第三人称是否出现异常裁切。
3. **微缩卧室。** 从二级菜单进入后，用左侧摇杆靠近开局正前方的床头柜腿，按住攀爬，再用另一指滑动环视。松开攀爬键后应落回地板。转动至两个横屏方向，检查按钮是否位于安全区域内，再用系统返回逐级回到主菜单。
4. **系统手势和设置。** 两个横屏方向都检查刘海与返回手势附近的控件。从局内用系统返回进入暂停，再试暂停页上的设置。滑到成长页底部，编辑小数、收起软键盘并保存。按住摇杆时切后台，回来应留在暂停页，点继续后应停在原地。连续重开三次，确认没有残留触控。保存一个容易识别的设置，再执行上面的 `am start -S -W` 强停后启动，确认值保留。
5. **性能。** 用中低端手机记录冷启动、连续重开和内存峰值。在沙盒设置 6～8 名巨人后重开，边走边连续拆楼约 30 秒。返回机型、Android 版本，以及明显卡顿发生在哪一段。

调试日志中 `first_menu_frame` 是引擎启动至菜单首帧的耗时，`round_ready` 是开局或重开的同步耗时，`frame` 每 5 秒记录帧率、P95 和最长帧耗时。复现后保存日志。如果要采样内存，在另一终端执行循环，测完按 **Ctrl+C**，回传峰值附近的记录。

```sh
adb logcat -d -v time -s godot AndroidRuntime > build/harbor-device.log
while :; do
  date '+%T'
  adb shell dumpsys meminfo org.gba.harboralert | grep -E 'TOTAL PSS|TOTAL RSS|^[[:space:]]*TOTAL[[:space:]]'
  sleep 1
done | tee build/harbor-memory.log
```

## 玩法

- **人类撤离**。观察界面右上角的箭头与距离，绕开巨人，进入东南角的绿色撤离圈。玩家每局在港区的可通行道路上随机出生。AI 巨人的搜索距离至少 150 米，并随体型增长到约自身身高，会优先追击视野里的玩家和 NPC。人类有三点生命。在移动中按住 **Shift** 疾跑并消耗体力，体力耗尽后回到步行。松开 **Shift** 恢复体力。
- **巨人沙盒**。按 **空格** 沿视角朝向踩踏，移动时则沿移动方向踩踏。橙色椭圆标示左脚鞋底的命中范围，初始约半秒后落脚。体型越大，抬脚、落脚和收脚的动画越慢。预警与命中跟随动画，收脚后的冷却为 0.72 秒。建筑被摧毁时立即切换至可行走的废墟碰撞，倒塌动画继续播放。相机附近的旧港区楼体使用约 3.5 秒的低模倒塌动画。巨人身高从 55 米长到 100 米时，相机会逐渐下移并俯看脚下，踩踏时镜头会顺势跟到预警落点。沙盒里可以遇到游走的人类 NPC。
- **成长模式**。每局开始时，玩家和 AI 都是人类：使用人类建模，没有加速奔跑，也不能主动攻击。默认从 1 厘米、100 生命和 10 攻击开始。最大生命、攻击和碰撞伤害都按当前身高同比例增长，受伤后成长保留生命百分比。场上默认生成 200 枚共享金币，开局生成首批，之后每 60 秒先清空剩余金币再刷新。界面显示最近金币的方向和距离。每捡一枚，身高乘以 1.1。达到「变成巨人的身高」（默认 3 米）后立即切换为巨人建模，并解锁踩踏、拆楼、抓取和挥拳；巨人皮肤在整局内固定，复活后再次变成巨人仍是同一套皮肤。人类之间只有撞击伤害：一方身高至少是另一方两倍时，较高的人类撞倒较矮的人类。每摧毁一栋楼，身高默认乘以 1.1。击倒对手后，如果对手的一半身高不超过自己，增加对手身高的一半。否则长到对手原来的身高。小体型 AI 会寻找金币、避开两倍以上身高的角色，并判断附近的对手是否值得攻击。解锁拆楼后，AI 会根据距离、双方体型和剩余生命选择追击、撤退或拆楼；巨人 AI 会把处于人类阶段的对手当作过去的行人 NPC 一样踩踏或抓起捏碎。
- 成长模式中所有成长角色都在镜头附近显示头顶血条，最大生命和攻击按实际身高缩放。角色受伤后若改变体型，会保留当前生命百分比。成长模式不再生成行人 NPC，场上的其他角色都是会从人类长成巨人的成长角色。
- **成长旁观**。旁观者模式使用自由飞行镜头，朝上看再前进即可升高，朝下看再前进即可降低。人类模式可在街上行走和疾跑，角色免伤。两种模式都无任务，场上的巨人全由 AI 控制，仍可查看身高排名。
- **大乱斗**。玩家和 AI 全程都是巨人。固定开局默认 25.2 米，开启「随机开局身高」后，每名巨人分别在设置的范围内抽取，默认 0.01～30 米。拆楼沿用成长模式的判定，身高奖励来自击倒其他巨人和拾取掉落的金币。击倒对手时沿用成长模式的身高公式。身高达到 50 米的巨人每击倒一名对手，就在脚下掉落一枚金币，记录击倒当时身高的 1%。身高低于 50 米的巨人可把这笔固定值加到自己的身高上。金币留在场上直到被拾取或重开。倒下后先抽取复活身高，再从所有存活巨人索敌范围之外的安全点加权抽取。靠近体型相近的巨人时权重更高，其他安全点也有机会。找不到范围外的安全点时才允许在范围内复活，仍需避开建筑和巨人碰撞。
- 大乱斗 AI 只把其他巨人作为攻击目标。有可拾取的附近金币时会主动拾取，空闲时持续游走。身高达到 40 米后，游走、追击和捡币的路线可以穿过建筑，移动时按原有规则碾碎碰到的楼体。
- **巨人手部攻击**。巨人沙盒和成长模式中，面向近处目标按 **Q** 捡起捏碎，按 **E** 挥拳。安卓使用同名按钮。捡起捏碎要求自己的身高至少是目标的 3 倍。挥拳要求较高一方的身高不超过较矮一方的 2 倍。目标在接触前离开范围、改变体型或被遮挡时可以躲开。动作可用在其他巨人、人类成长角色和可破坏建筑上。成长模式中的人类阶段不能使用任何手部攻击，变成巨人后才可攻击建筑与更小的角色。
- 巨人沙盒和成长模式的 AI 同时能踩踏和抓取同一目标时，每次出招有 90% 概率选踩踏、10% 概率选捡起捏碎。踩踏够不到时，AI 仍会尝试可用的手部攻击。
- 成长模式的玩家开局优先在随机道路点出生。AI 角色随后从全图的安全道路和空地中选点，每次尽量拉大与最近一名已出生角色的距离。开启「随机开局身高」后，每局首次出生的角色独立抽取身高，范围是设置的初始身高至成长身高上限之间。随机到「变成巨人的身高」以下时以人类 AI 出生，达到或超过门槛时以巨人 AI 出生。倒下后默认等待 5 秒，以满血和设置的初始身高在同一局复活。复活会避开倒下的位置，并在距最近存活巨人至少达到最佳间隔 95% 的安全点中随机选择。场上没有存活巨人时优先随机选择安全道路点。本命成长重新累计，已倒塌的建筑与本局击倒数保留。暂停会冻结复活倒计时。
- 较高巨人的身高达到另一方的 10 倍时，AI 不会主动追击、避让或重踏对方。发生身体碰撞时，较小的巨人会受到一次较大巨人的踩踏伤害。分开后再次碰撞可以再次命中。
- 成长模式和巨人沙盒中，按 **V** 可在任何身高切换第一人称和第三人称。第一人称下能低头看到自己的身体，头、脸部和头发会隐藏。手动选择在本局内生效，包括成长和复活。开局时，成长模式会按身高选视角，低于 1 米为第一人称，达到 1 米为第三人称。巨人沙盒默认使用第三人称。
- 成长模式默认从 100 米起每 50 米一个区间，每个区间只允许一名存活巨人。比如 150 米档已有人时，100 米档的巨人最高可以长到 149 米，最下面的巨人只能达到 99 米。上一个区间腾空后，会继续结算已取得的成长，依次给后面的巨人腾出空间。出生和复活也使用空档位。
- 玩家和 AI 巨人在每局成长模式开局时随机获得互不重复的名字，复活沿用本局名字。靠近其他巨人时，名字会显示在其血条上方。电脑端右上角按当前身高显示前五名和你的位置，按 **Tab** 展开或收起完整名单。安卓端点右上角的「排名」查看完整名单，上下滑动浏览，点「关闭」或使用系统返回键回到操作界面。看榜期间对局继续，触控留给名单浏览。身高相同时按出生顺序排列，复活中的巨人暂列在榜尾，复活后重新参与排名。
- 成长模式的三个角色都能在屏幕上方看到击杀播报。消息显示击倒双方的名字和致命动作，因人类撞击倒下时也会播报。最多保留最近 3 条，每条约 5 秒，暂停时冻结，重开时清空。
- AI 会优先处理可交战的巨人和人类。交战距离随体型缩放，至少为自身一个身位加踩踏范围，所以几百米高的巨人对走到一起也会互相踩踏，不会因为身体半径超过固定距离而互相无视。目标被连续遮挡 2 秒才会丢失，这期间 AI 仍会追踪其位置。人类撤离、巨人沙盒和成长模式的巨人可把完好建筑选作目标。附近没有可用目标时，AI 会在港区里随机游走。视野被建筑遮住时看不到对手的头顶血条。巨人血条显示距离为其身高的 1.5 倍，限于 2～45 米。
- 成长模式的步幅随身高缩放；金币在全图道路与空地分散刷新并避开存活角色附近，按渲染视距剔除显示，界面指南针始终指向全图最近的金币。命中对手巨人时，目标短暂闪红，成长模式玩家会看到屏幕中央的命中标记。
- 成长模式的巨人成为 40 米高后，可以走动撞毁建筑并直接穿过废墟。达到拆楼门槛后，低于 40 米每差一档 5 米，摧毁完好建筑就多需一次有效命中。35 米需要 2 次，30 米需要 3 次，默认解锁时的 3 米需要 9 次。来自不同体型的命中按各自的拆楼进度累加。
- 成长模式中，附近更高的巨人走路会引发镜头震动。距离相同时，身高差越大，震动越明显。人类阶段没有巨人脚步，不产生脚步震动；移动速度按身高缩放并使用「人类整体速度」，不受「巨人整体速度」影响。变成巨人后，玩家自己的落脚和踩踏会产生震动，移动速度使用「巨人整体速度」倍率。
- 人类撤离和巨人沙盒中，巨人默认初始身高约 25 米，脚底范围约宽 1.4 米、长 3 米。巨人解锁攻击后，左右脚每次落地都可命中脚底范围内的目标。普通落脚对生物造成伤害时，踩踏者身高至少与目标相同。脚停在原地时不会重复命中。走路落脚和重踏都会使镜头震动，重踏更强，镜头离落点越远震动越弱。
- 人类撤离和巨人沙盒中，每名巨人独立累计拆楼和解锁进度。拆满 3 栋后，从下一次攻击起，走路落脚和重踏都能一击拆楼。累计拆满 6 栋后，巨人只要碰到完好建筑就会立刻将其撞毁并继续全速前进。巨人对战中倒下可在同一局复活。
- 每摧毁一栋建筑，巨人的体型和脚底范围会平滑增长，直到达到该模式设置的身高上限，默认为 500 米。默认每次增长当前身高的 10%，累计的成长按顺序触发。达到上限后仍可踩踏和撞毁建筑。重开一局会恢复初始体型、拆楼计数和解锁状态。
- 默认设置下，人类撤离和巨人沙盒开局有 6 名人类 NPC。游戏每隔 6～10 秒尝试在玩家或巨人附近的安全道路刷新一名，场上最多 10 名。成长模式不使用这些行人。
- 巨人行走时平滑转向。松开方向键后，已经抬起的脚会向前落地，支撑脚保持站稳，随后平滑恢复默认站姿。摆腿期间按空格会在落脚后开始踩踏。
- 四种模式都用 **WASD** 移动，鼠标或方向键环视。按住左右键转动视角，按住上下键抬头或低头。按 **Esc** 暂停或继续。暂停和结算界面可重开本模式或返回港区菜单。

## 玩法设置

主菜单和暂停页都可打开「玩法设置」。每种模式分别保存，重启游戏后会载入上次保存的值。数值可以直接输入。地图边长使用正整数，数量使用整数，人类/巨人速度、初始身高、成长身高上限、基础生命和分档参数须大于零，两个忽略倍率须为非负数。巨人数量至少为一名。

| 选项 | 默认与生效时机 |
| --- | --- |
| 地图边长 | 默认 1,418 米。下一局按填写的边长生成正方形港区。48 米地图可保留中央十字街和四栋全尺寸厂房，更小的地图按可用空间裁掉放不下的街区和建筑 |
| 巨人数量 | 从下一局生效。巨人沙盒、成长模式和大乱斗由玩家控制第 1 名，其余由 AI 控制 |
| 人类整体速度 | 默认 1 倍。保存后立即影响撤离玩家和成长模式人类阶段的行走与冲刺，不受「巨人整体速度」影响；行人 NPC 的随机步速保持不变 |
| 巨人整体速度 | 成长模式和大乱斗默认 4 倍，人类撤离和巨人沙盒默认 1 倍。保存后立即影响当前局的巨人。成长模式的人类阶段不使用该倍率 |
| 巨人互相忽略的身高倍率 | 默认 10 倍，四个模式分别保存。体型差达到后 AI 不再主动追击对手，碰撞例外和接触踩踏共用该门槛 |
| 巨人忽略人类/行人的身高倍率 | 默认 30 倍，四个模式分别保存。体型差达到后 AI 巨人不再主动追击或踩踏该人类/行人；走路踩到仍按原有落脚伤害结算 |
| 巨人初始身高 | 从下一局生效。初始身高高于成长身高上限时，角色按输入的初始身高出生，达到成长上限的判定仍生效 |
| 成长身高上限 | 默认 500 米，从下一局生效 |
| 开局 NPC 数量 | 从下一局生效，仅使用行人 NPC 的模式读取 |
| 持续刷新 NPC | 保存后立即控制当前局是否继续刷新 NPC |
| NPC 平均刷新间隔 | 每次随机浮动 ±25% |
| 渲染视距 | 保存后立即控制场景渲染距离，并同步深度雾隐边界使远景平滑淡入海雾 |
| 镜头震动强度 | 设为 0 关闭（同步静音镜头震动低频轰鸣） |
| 自身震动 | 巨人沙盒、成长模式和大乱斗各自保存，默认开启。关闭后自身脚步、踩踏和拆楼引发的镜头震动立即停止，附近其他角色的震动仍按「镜头震动强度」计算 |
| 音效音量 | 默认 85%，支持 100% 以上的增益，设为 0 时静音。全局生效并即时调整战斗、交互与界面音效音量 |
| 环境音量 | 默认 60%，支持 100% 以上的增益，设为 0 时静音。全局生效并控制港区海风浪声与微缩卧室室内环境声 |
| 静音 | 默认关闭。开启后一键静音全局音频，保存后持久化 |

身高达到 150 米的其他巨人在渲染视距之外仍会显示淡淡的剪影。剪影随角色动作变化，近处建筑可以遮住它。

「成长模式」可以设置场上金币数量、金币刷新间隔、金币与拆楼各自的成长幅度、1 厘米时的生命与攻击，以及「变成巨人的身高」。金币数量设为 0 时不生成金币，成长幅度设为 0 时该来源不给予成长。随机开局身高在初始身高与成长上限之间对数采样，成长上限低于初始身高时使用初始身高。角色数超过预设名字池时，额外角色使用七位随机字母和数字，同局内保持唯一。桌面展开排名后可用滚轮浏览，触屏可上下滑动。

「大乱斗」可以单独设置随机开局的最低和最高身高、复活随机身高上限、金币掉落与拾取分界、掉落金币身高比例。随机开局范围从下一局生效。其他设置用于后续的复活、掉落和拾取判定，每枚金币保留掉落时记录的身高奖励。

随机开局会先按抽中的身高找安全出生点。港区放不下这个体型时，会排除这次抽中的身高及更大的体型，再从剩余区间均匀抽取。

「建筑刷新」默认关闭，打开后从每栋建筑被摧毁时起计时，默认等待 60 秒。等待时间到且原址无角色时恢复外观和碰撞。暂停会冻结计时，已获得的成长会保留。建筑刷新和成长规则从下一局生效。

巨人复活等待时间默认 5 秒，保存后从下次倒下时生效。「巨人互相忽略的身高倍率」默认 10 倍，「巨人忽略人类/行人的身高倍率」默认 30 倍。两项都按模式独立保存并立即生效，分别决定 AI 巨人对巨人和 AI 巨人对人类的主动追击门槛。

有巨人参与的碰撞中，身高相差至少 3 倍的角色可以互相通过。任一模式把「巨人互相忽略的身高倍率」设得低于 3 时，通过所需的身高倍率也随之降低。接触踩踏只在成长模式和大乱斗结算，按通过时的实际接触和当前模式的身高倍率结算。

## 场景与资产

- `scenes/main.tscn` 含主菜单、港区总览镜头和共用灯光。`scenes/round.tscn` 每局实例化同一张 `scenes/district.tscn`。
- `scenes/audio_manager.gd` 注册为全局 Autoload `HarborAudio`，搭配 `default_bus_layout.tres`（`Master` / `SFX` 含限幅器 / `Ambience` / `UI` 四总线）与 `assets/audio/`（由 `scripts/generate_audio.py` 生成的 44 个 WAV 音效与 2 个无缝循环 OGG 环境声）。3D 空间音效按巨人身高缩放音高与衰减距离，并带冷却节流、池化声道复用与暂停冻结；镜头震动配有深层地震轰鸣音效，随「镜头震动强度」与「自身震动」设置联动。
- `scenes/GirlBedroom.tscn` 独立加载 `assets/bedroom/GirlBedroom.glb`，复用 `scenes/human.tscn` 的角色模型和动画。1 Godot 单位为 1 米，角色碰撞高度为 0.01 米。地板和天花板使用导入的碰撞，墙壁和家具使用可见网格生成的碰撞，保留小尺度缝隙。室内净高为 2.9 米，地板表面位于 `Y = 0`，天花板下表面位于 `Y = 2.9`。项目默认使用 Compatibility，卧室的 SSAO、SSIL 和 SDFGI 仅在 Forward+ 下启用。
- `scenes/district_expansion.gd` 生成路网、建筑及随机出生候选点。`scenes/district.gd` 以固定距离控制游戏内的渲染区块，路面、地块和街景用分块 MultiMesh 合批。远处建筑会立即切换废墟碰撞，靠近时直接显示废墟。碰撞与 AI 视线查询独立于渲染。
- 成长模式单独调整路面、路缘和广场铺装的渲染高度，并提供近距离纹理。角色与金币的物理坐标以地面碰撞高度为基准。低于 1 米时，巨人的贴地移动量和地面吸附距离随身高缩放，以稳定厘米级镜头。
- `rust/src/` 包含回合流程、输入与角色控制、AI 寻路、踩踏和伤害规则。每帧由 `capture_pair_frames()` 缓存角色位置、碰撞半径、安全边距和步速，碰撞通过与接触踩踏两轮成对检查只读这份快照，并保持「移动前更新碰撞例外、移动和手部攻击后结算接触踩踏」的时序。`route.rs` 把每个障碍预先变换并分桶到它可能触及的寻路格，格点只检查身边障碍；AI 路线申请进入每帧 4 个、2.5 毫秒预算的队列，按角色序号轮转执行。玩家和镜头附近 120 米内的角色每帧更新程序化骨骼，120～240 米隔帧更新，更远的角色每三帧更新一次。Godot 场景负责地图、碰撞、镜头、骨骼动画、界面和效果。巨人的行走按实际运动距离推进步态，踩踏骨骼姿势与预警和命中时刻共用同一计时。
- 玩家与 AI 巨人每次出生和复活时，从 Kawaii、Hina 和 Chibi Catgirl 中独立等概率抽取外观。`scenes/giant_visual.gd` 用 Kawaii 骨架计算程序化动作及脚、手落点，`scenes/giant_skin.gd` 在各模型的骨架坐标系中传递动作。Hina 需要从蒙皮数据恢复绑定姿势，Chibi Catgirl 需要把四肢接到随动作更新的变形骨骼上，手指沿用原模型姿势。新增外观时检查脚底高度、第一人称头部遮挡和受击闪光。
- 道路使用 Breakwater District 的资源。`scenes/historic_buildings.gd` 生成旧港区三种建筑的低模外观和低模废墟。可行走的碰撞高度图位于 `assets/district/ruin_collision/`，与建筑视觉资源独立。
- `assets/characters/` 保留原始 GLB。Kawaii 巨人来自 `/home/nxneym/Downloads/kawaii/Anime+Girl+Kawaii.glb`，Hina 和 Chibi Catgirl 来自 `/home/nxneym/Downloads/fab/`，Kenney 人类来自 `/home/nxneym/Downloads/prototype/human_kenney.glb`。
